# Administracion-Configuracion-Software
Resumen interactivo sobre Administración de la Configuración del Software


## Control de Cambios

Flujo que seguimos para modificar el proyecto sin perder trazabilidad. En la página, cada etapa es interactiva: al seleccionarla se resalta y las anteriores quedan marcadas como completadas.

1. **Solicitud**: se propone el cambio y su motivo (por ejemplo, con un Issue).
2. **Evaluación**: se analiza el impacto, el riesgo y el esfuerzo.
3. **Aprobación**: el responsable acepta o rechaza el cambio (Pull Request).
4. **Implementación**: se aplica en la rama y se registra con un commit.
5. **Nueva versión**: se integra el cambio y se actualiza el historial.

## Auditoría de Configuración

Comprueba que lo aprobado fue lo que realmente se implementó:

- **Verificación**: cada elemento coincide con lo definido.
- **Revisión técnica**: un revisor distinto del autor evalúa el cambio.
- **Seguimiento de cambios**: el historial muestra que se siguieron los procedimientos de ACS.

## Reporte de Estado

Cada cambio registrado responde cuatro preguntas:

| Pregunta | Ejemplo |
|---|---|
| ¿Qué ocurrió? | Se agregó la sección Control de Cambios |
| ¿Quién lo hizo? | Ronald |
| ¿Cuándo ocurrió? | 15/10/2026 |
| ¿Qué se afectó? | index.html, README.md |
