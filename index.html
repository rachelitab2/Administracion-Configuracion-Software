¿Qué es la Administración de la Configuración del Software?

La Administración de la Configuración del Software (ACS) es un conjunto de actividades destinadas a controlar y gestionar todos los elementos que forman parte de un proyecto de software.

Su objetivo principal es mantener la integridad del sistema, garantizar la trazabilidad de los cambios y asegurar que los productos desarrollados conserven su calidad durante toda su evolución.

Control

Permite supervisar los cambios realizados en los componentes del sistema.

Trazabilidad

Ayuda a conocer quién realizó los cambios, cuándo ocurrieron y qué elementos fueron afectados.

Calidad

Contribuye a mantener la estabilidad y confiabilidad del software.

Identificación de Objetos de Configuración

La primera actividad del proceso ACS consiste en identificar correctamente los elementos que formarán parte de la configuración del software.

Objetos Básicos

  • Requisitos del sistema
  • Código fuente
  • Diagramas UML
  • Casos de prueba
  • Documentación técnica

Objetos Agregados

  • Módulos completos
  • Diseños generales
  • Subsistemas
  • Versiones completas
  • Configuraciones integradas

¿Por qué es importante identificar?

Una correcta identificación permite administrar cambios, controlar versiones, realizar auditorías y evaluar el impacto que tendrá una modificación sobre otros componentes del proyecto.

Control de Cambios

El control de cambios es el proceso que asegura que toda modificación al proyecto sea solicitada, evaluada y aprobada antes de aplicarse. Así se evitan errores, conflictos entre los miembros del equipo y cambios que nadie puede rastrear.

Haz clic en una etapa para recorrer el proceso.

1

Solicitud

Un miembro del equipo propone el cambio y explica qué quiere modificar y por qué (por ejemplo, con un Issue).

2

Evaluación

Se analiza el impacto: qué elementos de configuración afecta, qué riesgo tiene y cuánto esfuerzo requiere.

3

Aprobación

El responsable decide si el cambio se acepta o se rechaza (por ejemplo, al revisar un Pull Request).

4

Implementación

El cambio aprobado se aplica en la rama correspondiente y se registra con un commit descriptivo.

5

Nueva versión

Al integrar el cambio se genera una nueva versión identificada y el historial queda actualizado.

En la práctica con Git y GitHub

Issue (solicitud) → revisión del impacto (evaluación) → Pull Request aprobado (aprobación) → commit en la rama (implementación) → merge y etiqueta de versión (nueva versión).

Auditoría de Configuración

La auditoría comprueba que el software realmente cumple lo que se planificó y que los cambios se hicieron siguiendo los procedimientos acordados. Complementa al control de cambios, porque confirma que lo aprobado fue lo que se implementó.

Verificación

Confirma que cada elemento de configuración coincide con lo que se definió y que el cambio solicitado se aplicó correctamente.

Revisión técnica

Un revisor distinto del autor evalúa la calidad técnica del cambio: corrección, claridad y efectos sobre otros componentes.

Seguimiento de cambios

Se revisa el historial para asegurar que cada cambio quedó registrado y se siguieron los procedimientos de ACS.

Preguntas que debe responder una auditoría

  • ¿Se realizó el cambio que fue aprobado?
  • ¿Se hizo una revisión técnica del cambio?
  • ¿Se siguieron los procedimientos del proceso ACS?
  • ¿Quedó registrado quién, cuándo y qué se modificó?

Reporte de Estado

El reporte de estado mantiene informado a todo el equipo sobre la evolución de la configuración. Responde cuatro preguntas sobre cada cambio registrado.

¿Qué ocurrió?

Descripción del cambio realizado en el proyecto.

¿Quién lo hizo?

Miembro del equipo responsable de realizar el cambio.

¿Cuándo ocurrió?

Fecha en que se aplicó, para reconstruir el historial.

¿Qué se afectó?

Archivos o secciones del proyecto que cambiaron.

Conclusión

La Administración de la Configuración del Software es una disciplina esencial para garantizar la organización, control y calidad de los proyectos de software.

Gracias a sus actividades de identificación, control de versiones, gestión de cambios, auditoría y reporte, los equipos pueden desarrollar productos más confiables y fáciles de mantener.

Herramientas modernas como Git y GitHub representan una aplicación práctica de estos principios en entornos de trabajo colaborativo.
